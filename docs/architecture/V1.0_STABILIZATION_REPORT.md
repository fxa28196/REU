# v1.0 Stabilization Report

**Repository:** `fxa28196/REU` · **Tag:** `v1.0.0` · **Date:** 2026-07-28

The base simulation is complete and frozen. This records what was found, what was
changed, and what a v1.1 should tackle first.

**Headline:** the repository went from 536 to 338 tracked files and shed **79 MB**,
but the reason this pass mattered was not size. Three inventory passes found **live
correctness traps** — configurations that would silently run the wrong experiment.
Those are fixed. Every change was verified non-behavioral: after each one, arm A seed
42 was re-run and compared against its archived output. All 6,842 rows matched across
all 46 substantive columns, every time.

## 1. The correctness defects — the real reason for this pass

### The `scenarioCode` trap

Commit `948ac40` remapped the historical calibration reference from code `2` to code
`3`. **Three artifacts never followed:**

- `batch_params_histref_seed42.xml` and `batch_params_guidemo.xml` both set
  `scenarioCode=2` beneath a header reading *"HISTORICAL CAPACITY REFERENCE (2x99 real
  beds) — NOT a study arm"*.
- `parameters.xml` defaulted to `2`, labelled *"2=historical 2x99 beds"*.

But `ContextCreator.java:139-141` maps `2` → **Scenario C**. Re-running either file, or
pressing Run in the GUI, produced Scenario C while labelling itself the historical
reference — which is the model's **only empirical calibration point**, the basis of the
1.52× over-prediction reported in the chapter. Meanwhile `scenarioCode==3` had become
unreachable from every tracked configuration.

This did not corrupt the 27 published runs: those use explicit A/B/C batch files with
codes 0/1/2, which were and remain correct. The trap was latent, waiting for the next
person to re-run a calibration check.

**Fixed:** both batch files now set `3`; `parameters.xml` documents all four codes and
defaults to `0`, matching `ContextCreator`'s own fallback.

## 5. Code quality

Removed: the one unused import in the codebase (JTS `Point`); `setAgeRR` /
`setComorbidityRR` (never called — the weights they would set are pinned at 1.0 by
design under assumption A-09, and a comment now records why so nobody re-adds them);
`getVariables()` / `getAssumptions()` (nothing consumed the parsed rows); four
commented-out `RadioTower` signatures left from the stock demo.

**Wired up rather than deleted:** `chronic_physical` had a counter and getter nothing
read, so static analysis called it dead. But every sibling attribute is printed in the
population census and the value is exported per agent — the right fix was to *report*
it. The census now prints `chronic physical 0.396` against its published target of
0.391.

That distinction matters more generally: three of the inventory's "dead code" verdicts
turned out to be wrong on inspection (reflective bean access, GUI-only loading,
substring-matched grep hits). Static analysis proposes; verification disposes.

## 6. Architecture observations

**What is genuinely good, and worth preserving.** The governance registry is the
strongest idea in this codebase: `ScienceRegistry` refuses to start a run if a variable
claiming to be measured or literature-derived lacks a resolvable citation. A citation
defect stops the simulation rather than quietly becoming a result. The reproducibility
manifest is the second: every run records its commit, seed, per-input SHA-256, and
whether the tree was dirty — a flag that exists because an audit once caught nine runs
stamped with a commit that could not reproduce them.

**Where the structure strains.** The Python layer has no shared module, so the same
logic exists in many places: run-directory resolution in 4 files, Dijkstra in 3, the
matplotlib palette in 3 (with **two different palettes for the same three scenarios**),
`git_commit()` in 2. The population size `6842` is baked into 4 separate filenames, so
changing it means four coordinated edits — the exact class of error that already bit
this project once, when a hardcoded `finalA-n2037-seed42` path fed the previous
population's demand into a new optimum.

**A latent build hazard.** `build.gradle:40` compiles to `bin/`, while `.classpath`
directs the VS Code language server to `bin/main/`. `user_path.xml` scans `../bin`
*recursively*, so both trees are visible to the Repast classloader and can silently
drift — and `.vscode/settings.json` hides `bin/` from search, so the drift would be
invisible.

## 8. Recommendations for v1.1

Ranked by impact ÷ effort.

1. **Extract `scripts/_common/`** — `runs.py` (directory resolution + the triple
   load), `plotstyle.py` (one palette), `routing.py` (one Dijkstra), `provenance.py`.
   Absorbs the duplication and removes `n6842` from filenames. *High impact, low effort.*
2. **Resolve the `bin/` vs `bin/main/` collision.** One output directory. *High, low.*
3. **Add a JUnit regression fixture** asserting byte-identity against the archived
   baseline, so the check this report performed by hand runs automatically. *High, medium.*
4. **Consolidate the two results renderers** into one with two output profiles. *Medium, low.*
5. **Implement the awareness model.** The one sourced behavioral parameter — that 65%
   of surveyed unsheltered residents had never heard of the shelters — is still not
   implemented. Adding it as a swept Bernoulli would convert every access figure from
   an upper bound into an interval, and it is the largest single credibility gain
   available. *High, medium.*
6. **Order-independent two-phase admission**, retiring blocking assumption A-16. *Medium, medium.*
7. **Compare a needs-based triage policy** against first-come-first-served. This is the
   cheapest policy lever the model can test and hasn't: prioritise mobility-limited
   residents at the door and measure how much of the equity gap closes with no new
   beds. *High, low — and it is a publishable result.*
