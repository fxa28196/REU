# Phase 2 · Decision Record

Resolves the five open decisions from `00-PLAN.md` §7. Each entry states the
scientific question, the alternatives considered, the choice, and the reasoning.
**No decision here is silent.** Where a choice was directed by the project owner
rather than derived from evidence, that is stated explicitly.

Evidence classes follow `DESIGN_SPEC.md`: **M** measured · **L** literature ·
**C** calibrated · **A** assumption · **F** future work.

---

## D-1 — Amend the archived baseline manifest to record `evacuationThresholdUgM3`

**Question.** The baseline manifest lists six parameters but omits
`evacuationThresholdUgM3`, which is read every tick and drives the single
largest modelling decision in the model (when residents evacuate). Only prose in
`BASELINE_RESULTS.md` preserves its value. Should an archived artefact be
edited?

| Option | Consequence |
|---|---|
| **A. Leave the archive untouched** | Preserves the archived bytes, but leaves a behaviour-determining parameter unrecorded. An independent researcher reproducing from the manifest alone cannot know the trigger value — which defeats the manifest's stated purpose. |
| **B. Re-run and re-archive with a complete parameter list** | Edits an archived artefact, but the run is *behaviourally identical*: enumerating the parameter schema changes only what is written to `simulation.json`, not what the model does. |
| **C. Add the value as prose only** | Cheapest, but the manifest stays machine-incomplete and the next parameter added will be forgotten the same way. |

**Decision: B**, with the parameter list generated by enumerating the Repast
parameter schema instead of a hand-maintained array.

**Reasoning.** The manifest exists to make a run reproducible from itself. An
incomplete manifest that *looks* complete is worse than an obviously missing one
because it invites false confidence. The edit is cheaply verifiable: `agents.csv`
and `shelters.csv` must stay byte-identical, and no analysis check reads the
parameter block except `minutesPerTick`. Fixing the root cause at the same time
means this class of omission cannot recur. `BASELINE_RESULTS.md` will record that
the manifest was regenerated, that the run is behaviourally identical, and why.

**Risk accepted.** The archived `simulation.json` will differ from the one first
committed. Mitigation: a provenance note in the file and in the commit message,
with `agents.csv`/`shelters.csv` byte-identity as the evidence that behaviour did
not change.

## D-2 — Rename VWE

**Question.** "Vulnerability-Weighted Exposure" reads as an epidemiologically
derived quantity. It is not: it is an index with assumed weights, and at weights
of 1.0 it is numerically identical to raw exposure (`02-VULNERABILITY.md` §4).

**Alternatives.** "Exposure Burden Index" · "Susceptibility-Weighted Equivalent
Dose" · "Susceptibility-Stratified Exposure" · keep VWE with a mandatory caption.

**Decision — directed by the project owner**, who proposed *Exposure Burden
Index* and *Susceptibility-Stratified Exposure*. Both are adopted, for different
objects:

- **Exposure Burden Index (EBI)** — the *per-agent scalar*, units µg·m⁻³·h.
  Replaces "VWE" in all prose, figures, and reports.
- **Susceptibility-stratified exposure** — the *reporting approach* (D-3):
  exposure reported by age, mobility, and health group.

**Column-name policy (engineering decision made here).** The CSV contract in
`07-OUTPUTS.md` is **append-only**; renaming `vwe_ugm3h` would break every
existing consumer, including the archived baseline and both Python suites.
Therefore the **column keeps the machine name `vwe_ugm3h`**, `METRICS.md`
documents it as "Exposure Burden Index (EBI); historically VWE — machine name
retained for backward compatibility", and **all human-facing output says EBI**.
This separates human vocabulary from wire format and avoids a breaking change
for a cosmetic gain.

## D-3 — Adopt susceptibility-stratified reporting as the primary metric

**Question.** Should the headline result be a single weighted index, or exposure
reported separately by susceptibility group?

| Option | Defensibility |
|---|---|
| **A. Multiplied index as headline** (status quo) | Requires coefficients that have no verified source, are scale-ambiguous by roughly 2.5×, and can never be validated because no health outcome is simulated. |
| **B. Stratified reporting as headline** | Requires no unverifiable coefficient. Produces claims of the form "median dose before shelter arrival was X for agents with COPD vs Y without" — a statement about **exposure inequity**, which is what the model measures. |
| **C. Both — B primary, A as labelled sensitivity** | B's defensibility, plus a weighted view when a single number is needed. |

**Decision: C** — stratified reporting primary; the weighted index retained as a
clearly labelled sensitivity with weights defaulting to 1.0. **Directed by the
project owner** ("report: exposure by age / by mobility / by health group"), and
independently the recommendation of `02-VULNERABILITY.md` §5.

**Reasoning.** This is the most scientifically consequential decision of the
phase. Stratification moves the model's claim from one it cannot support (*how
much more harm* a group suffers — unknowable without simulating health outcomes)
to one it can (*how much more exposure* a group accrues, and mechanically why).
It also removes exposure to the failure mode that has already damaged this
project twice: a headline number whose provenance does not survive inspection.

**Consequence for interpretation.** Under a spatially uniform smoke field, group
differences arise from *time outdoors*, driven by travel distance and evacuation
timing. Every stratified difference must therefore be reported together with its
mechanical decomposition (`07-OUTPUTS.md` §4.2), or readers will over-read it as
a biological finding.

## D-4 — Model adults only

**Question.** The 2019 PIT counted 6 unsheltered minors (0.3% of 2,037). Include
them?

**Alternatives.** Include with adult parameters · include with child-specific
parameters · exclude and renormalise.

**Decision: exclude minors; model adults (≥18) only; renormalise the adult age
bands to sum to 1.**

**Reasoning.** Three independent arguments converge. *Statistical*: 6 people is
below the reporting floor for any subgroup result, and at n=50 it rounds to zero
agents. *Scientific*: every mobility and susceptibility parameter adopted in this
phase is an adult parameter — Bohannon's gait tables begin at age 20 and the
walking-speed meta-analysis has no under-20 stratum, so applying adult speeds to
minors would be invented extrapolation, while sourcing child-specific parameters
is a research task with no consumer. *Substantive*: unaccompanied-minor
homelessness is governed by separate legal and service systems, so the
shelter-access mechanism modelled here does not transfer without modification.

**Recorded limitation.** The modelled population is *adults* experiencing
unsheltered homelessness; results must not be described as covering the whole
unsheltered population.

## D-5 — Population scale

**Question.** The baseline runs 50 agents; the real event had ~2,037 unsheltered
people and 198 beds. What should production runs use?

| Option | Consequence |
|---|---|
| **A. Keep n=50** | Fast, but 2×99 capacity never binds, so refusals are structurally impossible and the equity question the model exists to ask cannot arise. |
| **B. n=500** | Capacity binds and runs stay fast, but the number corresponds to nothing measured. |
| **C. n=2,037 (the measured PIT count)** | Capacity binds at the real ratio (~10 people per bed); every agent count traces to a measurement. Slowest. |

**Decision: C for production runs — n = 2,037, the measured January-2019
unsheltered count — with n = 50 retained *solely* as the fast regression
fixture.**

**Reasoning.** 2,037 is not a modelling choice but `01-POPULATION.md`'s D10
measurement, which makes population size class **M** rather than class **A**. It
also reproduces the real scarcity ratio: ~2,037 people for 198 beds means roughly
90% cannot be sheltered *even under perfect placement* — the finding this study
is positioned to make. Choosing 500 would place an arbitrary number in the
denominator of every equity statistic.

**Engineering consequences, accepted.**
- Runtime scales as agents × ticks (2,037 × 18,720 ≈ 38M agent-steps). The
  per-tick parameter lookups and per-tick `GeometryFactory` allocation flagged in
  `08-ENGINEERING.md` §1.3 should be fixed first; both are output-neutral and
  byte-identity-verifiable.
- **Capacity binding makes agent step order outcome-determining** — otherwise the
  last bed is awarded by Repast's per-tick shuffle. Order-independent two-phase
  admission (`08-ENGINEERING.md` §3.5) is therefore a **prerequisite** for any
  n>198 result, not an optional refinement.
- Refusal counts must be reported across ≥3 seeds, never one.

**Baseline unaffected.** The archived baseline stays n=50, seed 42. Production
runs are new experiments archived under `docs/runs/<experiment-id>/`, never
overwriting it.

## D-6 — Refusal re-routing: remain in place, re-plan from the refusing shelter's node

**Question.** When a shelter fills between route selection and arrival, the
resident is refused at the door. Where does it go next? As implemented before
this decision (Finding A, `10-FAILURE-MODES.md`; registry assumption A-17), the
re-route was rebuilt from the *immutable start node*, so the resident walked a
straight off-network line back to its encampment before setting out again —
inflating travel distance, travel time and accrued dose for every refused
resident. That behaviour was an accident of implementation, not a model.

| Option | Consequence |
|---|---|
| **A. Re-plan from the resident's current node** (the refusing shelter's street node) | The resident stays where it stands and walks on to the next-nearest shelter with space, using the same network-nearest selection rule. No new behavioural parameter; every leg is a shortest path from where the person actually is. |
| **B. Model return-to-encampment as behaviour** | Would assert that refused people walk home before trying again — an empirical claim about evacuation behaviour with no supporting source. Also maximises exposure by construction. |
| **C. Queue at the full shelter** | Plausible real behaviour, but requires queue-discipline and abandonment parameters that have no source, and shelters here have no modelled departures for a queue to absorb. |

**Decision: A.** The refused resident remains at the refusing shelter's
location and selects the next shelter by the *existing* routing logic
(minimum street-network distance among operating shelters with space),
measured from its current graph node. Selection happens on the next tick,
preserving the established one-decision-per-tick cadence. Re-targeting remains
bounded (`MAX_RETARGETS = 8`) as a livelock guard; exhaustion → `REFUSED_ALL_FULL`.

**Reasoning.** A is the only option that adds no unsourced behavioural
parameter: it is the minimal correct completion of the already-documented
capacity rule (V12). B and C would each introduce assumptions the registry
cannot support. This matches A-17's registered sensitivity plan verbatim.

**Metric semantics preserved.** V11 `network_dist_to_shelter_m` keeps its
documented meaning — network distance from the *starting* node to the *first*
selected shelter (initial accessibility). Three QC columns are appended to
`agents.csv` (append-only contract, D-2): `planned_route_m` — the sum of all
planned leg lengths — `snap_gap_m` — off-network metres from the resident's
position to each leg's first waypoint (dominated by the encampment→street
snap; observed up to ~500 m for campsites far from a mapped street) — and
`door_refusals`. The analysis pipeline now enforces
walked ≤ planned + snap gap + 200 m as a **failing** check (A-17's guard,
formulated exactly as registered: "snap plus the sum of planned leg
distances"); the print-only version was itself a flagged defect (Finding A
note).

**Behavioural assumption remaining (A-17, now `active`).** Instant
re-decision at the door with full knowledge of remaining shelter capacity;
no queueing, no abandonment, no return-home choice. Future work.
