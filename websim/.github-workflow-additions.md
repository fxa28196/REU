# Proposed workflow additions (WP14) — NOTES ONLY, apply by hand

This file is the WP14 proposal for `.github/workflows/`. Nothing here is applied
automatically: a human reviews and pastes. Two changes are proposed:

1. a **lint step** in the existing `websim-ci.yml` jobs (the workspace now has
   `eslint.config.js` and `npm run lint`, wired into `npm run ci` before the tests);
2. a **GitHub Pages deploy workflow**, gated so that a green pipeline alone can
   never publish (see `websim/docs/DEPLOY.md` §0: public deploy sits behind the
   WP1 sign-off records, which are author-relayed approvals — keep a human in the
   loop).

---

## 1. Lint step for `websim-ci.yml`

Insert after the `typecheck` step (before the tests) in the `build` job, and in
`strict-artifacts` at the same position:

```yaml
      - name: Lint (eslint — no-console, react-hooks, jsx-a11y; WP14)
        run: npm run lint
```

Local parity already exists: `npm run ci` runs `npm run lint` before `npm test`.

## 2. Pages deploy workflow — `websim-deploy.yml` (proposed)

Design constraints this YAML encodes (do not lose them when editing):

- **Artifact runner only.** Hosted runners cannot rebuild the Java-derived graph
  assets (`pipeline/out/` is git-ignored; see DEPLOY.md §4). Same opt-in runner
  condition as `strict-artifacts`.
- **Manual trigger only** (`workflow_dispatch`) — no deploy on push.
- **Environment approval.** The `github-pages` environment must be configured in
  repo settings with **required reviewers**, so the publish step waits for a human
  who has read `websim/docs/DEPLOY.md` §0. This is the WP1 gate in mechanism form.
- **Both deploy gates run after the build, before the upload**: the pipeline gate
  (`check:deploy`, needs raw feed + salt on the runner — it refuses to pass
  without them) and the dist gate (`deploy-check`).
- **404 fallback is generated, never copied from `index.html`** (relative base —
  DEPLOY.md §3 explains why an index copy would half-load at bad paths).

```yaml
name: websim-deploy

on:
  workflow_dispatch:
    inputs:
      confirm:
        description: >-
          Type DEPLOY to confirm you have read websim/docs/DEPLOY.md section 0
          (WP1 sign-off records and their strength) and intend a public deploy.
        required: true

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: websim-deploy
  cancel-in-progress: false

defaults:
  run:
    working-directory: websim

jobs:
  build-and-gate:
    # Same opt-in artifact-runner condition as strict-artifacts: the graph
    # assets are Java-derived and absent from a hosted runner.
    if: ${{ vars.WEBSIM_ARTIFACT_RUNNER == 'true' && inputs.confirm == 'DEPLOY' }}
    runs-on: ${{ vars.WEBSIM_ARTIFACT_RUNNER_LABEL || 'self-hosted' }}
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22

      - name: Install
        run: npm ci

      - name: Full local gate (typecheck + lint + tests + claim linter + browser matrix)
        run: npm run ci

      - name: Build the site (stages pipeline/out, then vite build)
        run: npm run build -w app

      - name: Gate 1 — pipeline asset gate (WP4/Q4; refuses without raw feed + salt)
        run: npm run check:deploy -w @websim/pipeline

      - name: Gate 2 — dist gate (raw-encampment-data / manifest-mismatch / placeholder-marker)
        run: npm run deploy-check

      - name: Generate the 404 permalink fallback (DEPLOY.md §3 — never an index copy)
        run: |
          cat > app/dist/404.html <<'HTML'
          <!doctype html>
          <meta charset="utf-8" />
          <title>Redirecting to the simulation</title>
          <script>
            var segments = location.pathname.split("/");
            var base = segments.length > 1 && segments[1] !== "" ? "/" + segments[1] + "/" : "/";
            location.replace(base + location.search + location.hash);
          </script>
          <p>This address is not a page of the simulation. <a href="/">Open the simulation.</a></p>
          HTML

      - name: Upload Pages artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: websim/app/dist

  deploy:
    needs: build-and-gate
    # REQUIRED REVIEWERS must be configured on this environment in repo
    # settings — that reviewer approval is the human half of the WP1 gate.
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    runs-on: ubuntu-latest
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4

  post-deploy-dry-run-reminder:
    needs: deploy
    runs-on: ubuntu-latest
    steps:
      - name: Dry-run checklist reminder
        run: |
          echo "Deploy is live. WP14 acceptance requires the dry run ON THE PRODUCTION URL:"
          echo "  websim/docs/DEPLOY.md section 5 — execute all 7 steps and record the"
          echo "  result in a dated note under websim/docs/. A failed step = roll back first."
```

## 3. Not proposed (and why)

- **Deploy on push / on tag** — rejected: the WP1 records are author-relayed
  approvals with no written determination on file; publishing must stay a
  deliberate human act (two confirmations: the dispatch input and the environment
  reviewer).
- **Copying `index.html` to `404.html`** — rejected: `base: "./"` makes asset URLs
  relative to the current path, so an index copy served at a deep bad path would
  fetch assets from the wrong place and half-load. The generated redirect page
  preserves `location.hash`, which is where permalinks live.
- **A hosted-runner deploy with committed assets** — rejected for now: it would
  require committing ~7 MB of brotli graph assets (or LFS) plus the archive
  bundles, and the manifest-mismatch rule would then guard git bytes instead of
  the pipeline's. Revisit only with a decision record.
